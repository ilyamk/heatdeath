# Быстрый старт

[English version / Английская версия](QUICKSTART.en.md)

Пошагово, без теории. Если хотите понимать, *почему* каждый шаг такой —
[docs/ru/THREAT-MODEL.md](docs/ru/THREAT-MODEL.md).

Времени: около 30 минут. Понадобится игральный кубик и бумага.

## Safe/DAO cold owner: сначала репетиция

Если нужен один cold или recovery owner для Safe, используйте специальный профиль,
а не общий мастер кошелька. Репетиция содержит только публичные тестовые данные.

```sh
npm run rehearse:safe-owner
npm run doctor
npm run safe-owner
```

Перед реальной командой прочитайте [docs/ru/SAFE-OWNER.md](docs/ru/SAFE-OWNER.md).
Генерируйте каждого Safe owner независимо. Команда не разворачивает Safe и не
подписывает транзакции.

## Сначала решите, ГДЕ запускать

Это решение важнее всех остальных в документе. Инструмент — обычный процесс
на вашей машине: у него нет ни своего контейнера, ни виртуалки. Модель
разрешений Node запрещает ему выходить наружу (сеть, запись, подпроцессы), но
**не мешает другим программам смотреть внутрь него**.

| Вариант | Что даёт | Чего не даёт |
|---|---|---|
| **Выделенное железо** — SeedSigner, Coldcard, Passport | Сид вообще не попадает в ОС общего назначения. Нет ни радиомодулей, ни других процессов | Нужна покупка; наш инструмент используется только для сверки |
| **Отдельный x86-ноутбук с Tails на USB** | Установленная ОС **не запущена вообще**, ничего не пишется на диск | **Не работает на вашем Mac** — см. ниже |
| **UTM на чистом Mac** | Чистая одноразовая ОС без накопленного мусора, гарантированное отсутствие сети, ничего не остаётся после удаления ВМ | **Не граница от самого macOS** — см. ниже |
| **Обычная сессия macOS** | Быстро | Базовый уровень: всё из [docs/ru/THREAT-MODEL.md](docs/ru/THREAT-MODEL.md) |

## Вариант Tails: полностью в обход установленной ОС

**У вас M5 Max, и на нём Tails не запустится.** Tails требует
[64-битный x86-64](https://tails.net/doc/about/requirements/), и в документации
прямо сказано, что он не работает на «Mac computers with an Apple processor
(M1, M2, and so on)». Нужен **другой компьютер**: любой x86-64 ПК или старый
Intel-Mac.

Смысл варианта в том, что установленная на диске система в этот момент **вообще
не исполняется**. Компрометация macOS перестаёт иметь значение, потому что macOS
не запущен.

### Что понадобится

- x86-64 компьютер (не Apple Silicon)
- USB-флешка от 8 ГБ для Tails
- Вторая флешка для нашего инструмента
- Кубик и бумага

### Подготовка (можно на Mac, пока онлайн)

1. Скачайте образ Tails с [tails.net](https://tails.net) и **проверьте подпись**
   по инструкции на их сайте. Это не формальность: подменённый образ Tails —
   ровно тот сценарий, ради которого всё остальное делается.
2. Запишите его на первую флешку.
3. На вторую флешку положите:
   - релизный бинарник v2.2 `heatdeath-linux-x64`;
   - подписанный `SHA256SUMS` и независимо полученные fingerprints публичных
     ключей, по которым проверялся релиз;
   - при желании `heatdeath.mjs` и точный архив Node linux-x64, если хотите
     запускать основной читаемый артефакт.

Пока сеть ещё доступна, проверьте полный релиз по
[docs/ru/VERIFY.md](docs/ru/VERIFY.md), затем отдельно запишите ожидаемый SHA-256
Linux-бинарника. Нативный артефакт убирает установку Node из офлайн-церемонии;
читаемый бандл `.mjs` остаётся основным объектом аудита.

### Генерация

1. Загрузите x86-компьютер с флешки Tails. **Persistent Storage не настраивайте** —
   амнезия и есть смысл Tails.
2. Отключите сеть в Tails (он и сам умеет стартовать без неё).
3. Подключите вторую флешку, скопируйте бинарник во временную файловую систему
   Tails и сравните с хешем из подписанного манифеста:

```sh
cp /media/amnesia/*/heatdeath-linux-x64 /tmp/heatdeath-linux-x64
sha256sum /tmp/heatdeath-linux-x64
chmod 0755 /tmp/heatdeath-linux-x64
```

4. Запустите встроенный self-test, затем нужную церемонию. Строгие флаги модели
   разрешений уже встроены в SEA:

```sh
/tmp/heatdeath-linux-x64 --self-test
/tmp/heatdeath-linux-x64 --wizard --dice
```

Для холодного/резервного владельца Safe используйте `--safe-owner` вместо
`--wizard --dice`.

5. Дальше — как обычно: кубики, запись на бумагу, обязательная сверка.
6. Выключите компьютер. Tails ничего не сохранил: оперативная память
   затирается при выключении, диск не трогался.

## Вариант UTM: полезен, но это НЕ граница безопасности

Короткий ответ на вопрос «будет ли ВМ защищённым контейнером от остального
macOS»: **нет, не в ту сторону.**

Виртуальная машина защищает **хост от гостя**. Нам нужно обратное — защитить
гостя от хоста. Этого ВМ не делает, и вот почему конкретно:

- **Оперативная память гостя — это область памяти в процессе UTM**, который
  работает под вашим пользователем. Измерено на этой машине: карта памяти
  любого процесса того же UID снимается снаружи обычной утилитой `vmmap`, без
  root. Сид внутри ВМ находится в памяти, доступной хосту.
- **Снапшот ВМ записывает память гостя в файл на диске хоста** — вместе с сидом.
- **Нажатия клавиш идут через ввод хоста**, а окно ВМ снимается скриншотом
  как любое другое.
- **Образ диска гостя — обычный файл** в вашей файловой системе.

То есть если macOS скомпрометирован, ВМ не даёт почти ничего.

### Когда UTM всё же осмыслен

Если хост чистый, ВМ — **заметное улучшение** относительно повседневной сессии:

- чистая ОС без накопленных расширений, менеджеров буфера и агентов синхронизации;
- сеть отключается жёстко — просто не добавляйте сетевой адаптер в конфигурацию ВМ;
- ничего не остаётся: удалили ВМ — удалили всё.

### Как настроить, если идёте этим путём

1. Гостевая ОС: любой Linux под arm64 (Debian, Ubuntu). Tails внутри ВМ ставить
   бессмысленно — его амнезия защищает от хоста, которого в этой схеме нет.
2. В конфигурации ВМ: **удалить сетевой адаптер**, выключить общий буфер обмена
   и общие папки, выключить общий доступ к каталогам.
3. Передать бандл в гостя один раз — через образ диска или временную общую
   папку, которую потом отключить.
4. **Никогда не делайте снапшот** ВМ, в которой есть сид: снапшот пишет память
   гостя на диск хоста.
5. Внутри гостя — как обычно: `node --permission ... heatdeath.mjs --wizard --dice`.
6. После записи фразы на бумагу удалите ВМ целиком.

> Итог по изоляции, честно: UTM убирает *накопленный мусор вашей рабочей
> системы*, но не убирает *саму систему*. Единственный вариант, который убирает
> её целиком, — не запускать её: Tails на отдельной x86-машине или выделенное
> железо.

## Самый простой путь

```sh
npm run wizard
```

Мастер проведёт через все шаги ниже по порядку и не даст пропустить сверку.
Остальная часть документа — то же самое вручную, если предпочитаете контроль.

## Шаг 1. Пока вы онлайн

Отдельный локальный каталог, **не** синхронизируемый с iCloud, Dropbox или
Google Drive.

```sh
git clone https://github.com/ilyamk/heatdeath.git
cd heatdeath
rm -rf node_modules
npm ci --ignore-scripts
npm audit --omit=dev
npm run self-test
npm run prove-sandbox
```

Ожидаемый результат: `Self-test OK` и `6/6 capability probes denied`.
Если что-то не так — **не продолжайте**.

Сохраните хеши файлов отдельно (например, сфотографируйте экран телефоном,
который потом не участвует в генерации):

```sh
shasum -a 256 generate.mjs slip39.mjs package.json package-lock.json
```

## Шаг 2. Подготовьте терминал

Это не формальность. Атаковать будут скроллбэк, а не криптографию.

- **iTerm2 → Settings → General → Magic → выключить Instant Replay.**
  Он пишет содержимое сессии на диск, даже если вы ничего не сохраняли.
- Там же: Profiles → Terminal → снять «Unlimited scrollback».
- Выйдите из менеджеров буфера обмена: Raycast Clipboard History, Paste, Alfred.
- Не запускайте внутри `tmux` или `screen`.
- Закройте браузеры и мессенджеры.
- Убедитесь, что каталог не попадает в Time Machine.

## Шаг 3. Отключите всё

Wi-Fi, Ethernet, Bluetooth, AirDrop, Screen Sharing, Continuity.

Инструмент предупредит, если увидит поднятые интерфейсы, но проверить —

## Шаг 4. Сгенерируйте

```sh
npm run generate:dice
```

1. Бросьте кубик **не менее 128 раз** и введите результаты цифрами 1–6.
   Ввод скрыт, эхом возвращается только счётчик.

   > **Это настоящий физический кубик, а не генерация системой.** В этом весь
   > смысл: числа берутся не из компьютера. Не бросайте по одному — киньте
   > горсть из 5–6 кубиков и прочитайте слева направо: 128 бросков — это
   > примерно 22 броска горстью из шести или 26 из пяти, 5–7 минут.
   >
   > Вводить можно **частями**: нажали Enter после горсти, счётчик обновился,
   > продолжайте. Ничего не теряется между партиями. `cancel` на пустой строке
   > переключит на автоматический режим.
   >
   > **Отказаться от кубиков — нормально.** Тогда вы получаете 256 бит из трёх
   > источников ОС, и это полноценный безопасный кошелёк. Кубики закрывают один
   > конкретный сценарий: сломанный или закладочный ГСЧ самой ОС. Они
   > подмешиваются по XOR и не могут ухудшить результат.
2. На вопрос про passphrase нажмите Enter (пустой = стандартный кошелёк).
   Если решите её задать — прочитайте предупреждение целиком: забытая
   passphrase означает безвозвратную потерю средств.
3. **Перепишите 24 слова на бумагу от руки.** Не фотографируйте.
   Не копируйте. Не вводите никуда, кроме следующего шага.
4. Сверьте написанное со строкой `read-back`.
5. Запишите отдельно `master fingerprint` и адрес **индекса 1**.

> Почему индекса 1, а не 0: у обеих схем деривации путь при `i = 0` буквально
> совпадает, и fingerprint от схемы не зависит. Ни то ни другое не отличит
> схему `metamask` от `account`. Индекс 1 — отличит.

---

## Шаг 5. Проверьте, что записали правильно

Не пропускайте. Ошибка при переписывании — самая частая причина реальных
потерь, далеко впереди любых атак.

```sh
npm run verify
```

Вводите фразу **с бумаги**, а не с экрана. Должны совпасть и fingerprint,
и адрес индекса 1.

Если инструмент говорит, что слова нет в словаре, — он подскажет ближайшие.
Если говорит, что чек-сумма не сошлась при всех верных словах — нарушен
**порядок** слов.

---

## Шаг 6. Защитите бумагу от потери

Одна бумажка — единая точка отказа.

```sh
npm run split -- --shares=2of3
```

Получите три доли. Любые две восстанавливают кошелёк, одна не даёт **ничего**.
Разложите по трём разным физическим местам. Две доли в одном ящике — это одна
доля с лишними шагами.

Проверьте, что доли работают, **до того как положитесь на них**:

```sh
npm run combine
```

Введите любые две доли и убедитесь, что получилась та же фраза и тот же адрес.

## Шаг 6б (необязательно). Перенос через 1Password

Если вы пользуетесь 1Password и не хотите переписывать десяток секретов руками,
есть команда, которая складывает всё сгенерированное в одну запись — как
**перевалочный буфер на момент создания**, который вы потом удалите.

### Что поставить заранее

```sh
brew install --cask 1password          # приложение, если ещё нет
brew install --cask 1password-cli      # CLI, даёт команду `op`
op --version                           # проверка
```

Затем в приложении: **1Password → Settings → Developer → «Integrate with
1Password CLI»**. Без этой галочки ничего не заработает.

Убедитесь, что связка жива, — приложение спросит Touch ID:

```sh
op vault list
```

### Сначала репетиция

```sh
npm run op-export:dry
```

Пройдёт весь путь и должен закончиться строкой
`DRY RUN succeeded - op accepted the item and wrote NOTHING`. Ничего не
записывает. Вопросы те же, что в боевом прогоне.

### Два режима

Команда спросит `new or existing?`

| Режим | Когда |
|---|---|
| **`new`** | Кошелька ещё нет. Команда сгенерирует его сама (с кубиками, если захотите), покажет фразу, **дождётся, пока вы запишете её на бумагу**, поделит на доли SLIP-39 и всё сложит |
| **`existing`** | Фраза уже есть. Вводите 24 слова с бумаги; дальше то же самое |

В обоих случаях перед записью печатается **master fingerprint** и **адрес
индекса 1** — сверьте с тем, что записывали.

### Боевой прогон

```sh
npm run op-export
```

1Password попросит подтверждение. В конце команда напечатает готовую строку
удаления записи.

### Что надо понимать

> **Три доли SLIP-39 в одном хранилище — не пороговый бэкап.** Это секрет в
> одном месте. Для короткоживущего буфера приемлемо, для хранения — нет.
>
> **Удалите запись**, как только разложили содержимое: доли — в три разных
> физических места, фразу — на бумагу.
>
> Сид при этом покидает машину: 1Password синхронизирует его на свои серверы
> в зашифрованном виде.
>
> Команда работает при **5/6** вместо 6/6, потому что ей нужно запускать `op`,
> а `op` наш рантайм не ограничивает никак. Поэтому это отдельная команда —
> генерация и мастер сохраняют полную песочницу.

Если вам нужно **хранение**, а не буфер, — держите в 1Password **одну** долю
SLIP-39. Ниже порога доля не даёт ничего, и компрометация хранилища безвредна.

Подробный разбор векторов: [README.ru](README.ru.md#какие-векторы-это-добавляет--и-что-с-ними-сделано).

## Шаг 8. Прежде чем переводить деньги

1. Импортируйте фразу в MetaMask или Rabby. Адреса обязаны совпасть с теми,
   что вы записали.
2. Переведите небольшую сумму. Убедитесь, что она видна и что вы можете
   отправить её обратно.
3. Только после этого переводите значимые суммы.

## Чего делать нельзя

- Фотографировать фразу или доли.
- Хранить в заметках, менеджере паролей, облаке, мессенджере — где угодно
  в цифровом виде.
- Вводить фразу на любом сайте. Ни на одном. Никогда.
- Использовать один и тот же сид для «горячего» кошелька и для сбережений.

## Если сумма серьёзная

Аппаратный кошелёк снимает с вашего компьютера всю модель угроз целиком: сид
никогда не оказывается в памяти машины общего назначения. Сгенерируйте там,
а этот инструмент используйте в режиме `npm run verify`, чтобы независимо
подтвердить адреса. Подробнее — [docs/ru/COMPARISON.md](docs/ru/COMPARISON.md).
