# Contributing

Patches are welcome. Two things to read first: how this project judges a
change, and the licence terms your contribution comes under.

---

## What a good change looks like here

This project's argument is not "trust us". It is "run this command and see for
yourself". Contributions are held to that:

- **Claims are measured, not asserted.** If a change says something is safe,
  fast or denied, show the command that demonstrates it. Several things in
  this repository were found only because a claim was tested rather than
  believed - a GF(256) table generated by doubling instead of by (x+1), a QR
  format-information strip written transposed, an echo race that put a
  recovery phrase on screen.
- **Negative tests count.** A guard that has never been observed firing has
  not been tested. `--self-test` deliberately includes tests that a defect
  must break.
- **No new runtime dependencies** without a strong argument. The dependency
  tree is five audited packages, and that is a feature.
- **Do not weaken the sandbox.** `npm run prove-sandbox` must stay at 6/6 for
  every command that touches a secret. `--op-export` runs at 5/6 and is a
  separate command precisely so the boundary stays visible.
- **Keep the honesty.** The documentation states where this tool loses to
  competitors and which of its own defences would not have caught a real bug.
  Do not "improve" those passages into marketing.
- **Documentation comes in pairs.** Every document exists twice: `docs/en/X.md`
  and `docs/ru/X.md`, mirroring each other file for file, and the same holds for
  `README.en.md` / `README.ru.md` and `QUICKSTART.en.md` / `QUICKSTART.md`.
  A translation is a snapshot, and a snapshot drifts the moment one side is
  edited. **Changing one language version obliges you to change the other in the
  same pull request.** If you cannot write the second version, say so in the pull
  request and it will be handled - an acknowledged gap is fine, a silent one is
  not. Two things must survive translation unchanged in meaning: the passages
  naming who beats us, and `docs/*/ENTROPY.md`, which explicitly refuses the
  Landauer energy argument at the 2^128 level. Both are load-bearing.
- **New terms belong in the glossary.** If a change introduces a specialist term
  into any document, add it to `docs/en/GLOSSARY.md` and `docs/ru/GLOSSARY.md`,
  pointing at the document that explains it. The two glossaries must hold the
  same set of entries.

Before opening a pull request:

```sh
npm run self-test
npm run prove-sandbox
npm run build          # must reproduce byte-identically
```

### Why this exists, stated plainly

Without it, this project could not offer a commercial licence. AGPL-3.0 is
deliberately unsuitable for anyone who wants to ship a closed product, and the
intended answer for those people is to buy a separate licence. That is only
possible if one party can license the whole work - and after a single merged
pull request without clause 2, that stops being true for the code it touched.
Retroactive fixes require tracking down every past contributor, which in
practice means the option is gone.

You are giving up something real: the ability to stop this code being used in
a proprietary product. If that is not acceptable to you, that is a legitimate
position - say so in the pull request and it will not be merged, with no hard
feelings. An unmerged patch is better for both of us than an unclear one.

## Reporting a security problem

Do not open a public issue for a defect that could cost someone their funds.
Contact the maintainer privately first - see the contact section in
[NOTICE.md](NOTICE.md).

Please include what you ran and what happened. A failing command is worth more
than a paragraph of description.
