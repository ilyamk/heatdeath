## Порядок доверия

1. **Читаемый исходник** — `generate.mjs` и `slip39.mjs`. Максимум доверия:
   вы читаете то, что исполняется.
2. **Бандл** `dist/heatdeath.mjs` — 300 КБ, без зависимостей, читается
   человеком, воспроизводим побайтово.
3. **Бинарник** `dist/heatdeath` — 144 МБ. Только удобство. Считайте
   непроверенным, пока не воспроизвели его SHA-256 сами.

Чем ниже по списку, тем больше вы доверяете кому-то другому.

## Проверка релиза

Обычные команды в checkout исходников исполняют этот checkout через
`build/run-source.mjs` и предупреждают, что релизные подписи его не покрывают.
Для строгой границы подписи скачайте полный набор артефактов в `dist/` и используйте
явные команды `:verified`.

```sh
npm run verify-release -- --trusted-keys=/absolute/independent/key-directory
# добавьте --require-all, если скачан также SEA для darwin/arm64
```

Проверяющий сначала валидирует все три подписи, затем разбирает `SHA256SUMS`
строгой грамматикой. Абсолютные пути, `..`, неожиданные имена, дубликаты и
некорректные хеши приводят к отказу. Bundle, детерминированный архив исходников,
provenance и рецепт сборки обязательны; большой SEA опционален, если не указан
`--require-all`.

Скачивание GitHub Release не сохраняет Unix-бит исполнения SEA. Восстановите эти
локальные метаданные только после успешной проверки:

```sh
chmod 0755 ./dist/heatdeath
```

Ожидаемый результат:

```
==> signatures
  ok    ed25519 …fingerprint…
  ok    ml-dsa-87 …fingerprint…
  ok    slh-dsa-sha2-128s …fingerprint…

==> artifact hashes
  ok    heatdeath.mjs
  ok    heatdeath-v2.1.0-source.tar.gz
  ok    heatdeath-v2.1.0.spdx.json
  ok    SOURCE-PROVENANCE.json
  ok    BUILD-RECIPE.txt
  --    heatdeath SEA absent (optional)
```

### Что это доказывает и чего не доказывает

Зелёный результат означает: файлы соответствуют манифесту, а манифест подписан
тем, кто владеет независимо предоставленными ключами.

**Если публичные ключи пришли той же загрузкой, что и артефакт, — это
замкнутый круг.** Атакующий, подменивший бинарник, подписал бы его своими
ключами и приложил бы их же.

Подпись начинает что-то значить только после того, как вы сверили **отпечатки
ключей с источником, отличным от самой загрузки**. Параметр `--trusted-keys`
делает эту границу доверия явной. Без него проверяющий предупреждает о
циклическом доверии.

## Воспроизведение сборки

Самый сильный из доступных механизмов: не «поверьте подписи», а «соберите сами
и сравните».

```sh
npm ci --ignore-scripts
npm run build
# полная tagged-сборка darwin/arm64: npm run build:release
```

Подробности и точные версии — `dist/BUILD-RECIPE.txt`.

- **Бандл `.mjs` воспроизводим на любой машине** с той же версией esbuild.
  В нём нет ни абсолютных путей, ни временных меток.
- **Бинарник воспроизводим только против той же сборки Node** (v26.7.0,
  darwin/arm64), потому что содержит рантайм целиком.

Две тонкости, установленные измерением:

- esbuild должен запускаться **из корня репозитория с относительным путём**
  ко входному файлу. Абсолютный путь протекает в бандл комментариями и делает
  хеш машинозависимым.
- Имя выходного файла бинарника фиксировано: ad-hoc `codesign` встраивает имя
  как идентификатор подписи, и переименование меняет байты.

Если хеши не сошлись — **не запускайте артефакт**. Читайте исходник: бандл
потому и объявлен основным артефактом, что для его аудита сборка не нужна.

## Почему `--prove-guard` внутри бинарника ничего не доказывает

```sh
npm run prove-guard:verified      # подписанный bundle; только capability scope
./dist/heatdeath --prove-guard    # из бинарника — само по себе не доказательство
```

Бинарник содержит исходник **открытым текстом**: `strings` достаёт его дословно,
включая флаги песочницы. Пропатченная сборка напечатает те же `6/6 denied`,
продолжая делать что угодно. Самоаттестация артефакта, который контролирует
атакующий, — замкнутый круг.

Верить этому выводу можно, только если вы запустили его из прочитанного вами
исходника или из сборки, которую воспроизвели сами.

## Проверка самого кошелька

Отдельно от целостности файлов: убедиться, что записанная фраза восстанавливает
именно тот кошелёк.

```sh
npm run verify
```

Вводите фразу **с бумаги**, не с экрана. Сверяйте `master fingerprint`
и адрес **индекса 1**.

> Индекса 1, потому что при `i = 0` пути обеих схем деривации совпадают, а
> fingerprint от схемы не зависит. Ни то ни другое не отличит `metamask` от
> `account`, и проверка не той схемой прошла бы «успешно», оставив неверными
> все адреса начиная с первого.

## macOS: молчаливая смерть бинарника

Скачанный браузером бинарник получает `com.apple.quarantine`, и Gatekeeper
убивает его **без единого сообщения** — exit 137, пустые stdout и stderr.
Выглядит как «ничего не происходит».

```sh
xattr -d com.apple.quarantine ./heatdeath
```

Мы не нотаризуем сборки: это $99/год и привязка к юридическому лицу, что
противоречит псевдонимности подписей.

## Как проверен QR-кодер

`qr.mjs` реализует ISO/IEC 18004 (байтовый режим, ECC L и M, версии 1–40).
Проверяется двумя внешними оракулами, ни один из которых не является нашим кодом:

1. **Детектор OpenCV расшифровывает наш вывод** обратно в исходную строку.
   Это проверка валидности в том виде, в каком её испытывает телефон.
2. **Матрица совпадает с Python-библиотекой `qrcode` побитово** при
   закреплённой маске. Закрепление обязательно: маска выбирается по штрафным
   очкам, и две корректные реализации законно выбирают разные, после чего
   не совпадают вообще ни в одном модуле.

Результат сверки: **6/6 матриц идентичны эталону** на версиях 1, 3, 7, 11, 15
и 17 — то есть на обеих границах, где меняется разрядность счётчика символов
(v10) и появляются блоки версии (v7).

Отдельно проверено, что рендер в терминал не искажает матрицу: полублочный
вывод разбирается обратно и совпадает с исходной матрицей (9/9), а зона тишины
остаётся чистой.

**Почему потолок — версия 12.** Не ограничение кодера. Измерено: символ версии
17 (85×85) детектор OpenCV не читает ни при каком масштабе — **и не читает его
у эталонной библиотеки тоже**. Значит это предел детектора, а не дефект
кодирования. Версия 15 читается надёжно; 12 оставляет запас на камеру телефона
и шрифт терминала. Списки, не помещающиеся в один символ, разбиваются на части
с заголовком `part i/n`: два QR, которые сканируются, лучше одного, который нет.

Два бага, найденных именно этими оракулами и невидимых иначе:

- **Формат-информация была транспонирована.** Все остальные модули корректны,
  символ выглядит правильным, не читается ничем. Расхождение с эталоном при
  закреплённой маске составляло 9 модулей и указало прямо на строку 8 и колонку 8.
- **Цикл резервирования затирал always-dark модуль** в позиции `(size-8, 8)`.
  Расхождение — ровно **один** модуль из 7225.
