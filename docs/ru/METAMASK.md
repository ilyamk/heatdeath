Разбор по исходному коду. Цель — показать, **где именно** расширение слабее
всего, чтобы вы понимали, что именно этот инструмент вам даёт, а что нет.

Провенанс размечен: **[код]** — файл прочитан, указаны строки; **[док]** —
документ или адвайзори по ссылке; **[не подтверждено]** — установить не удалось.

Опорные коммиты: `MetaMask/metamask-extension` @ `1d57eff` (v13.46.0),
`MetaMask/accounts` @ `c6a32ba`.

## 1. Хорошая новость: генерация действительно локальна

**[код]** Полная цепочка от нажатия «Create a new wallet»:

```
ui/pages/onboarding-flow/onboarding-flow.tsx:278   FirstTimeFlowType.create
  → ui/store/actions.ts:1153                       createNewVaultAndGetSeedPhrase
  → app/scripts/services/legacy-background-api-service.ts:3920   (порт, не сеть)
  → @metamask/keyring-controller KeyringController.ts:1004 → :2992
  → @metamask/eth-hd-keyring hd-keyring.ts:141     generateRandomMnemonic()
  → @metamask/scure-bip39 src/index.ts:36          strength = 128 по умолчанию
  → @noble/hashes 1.3.3 src/utils.ts:236           crypto.getRandomValues
```

**12 слов / 128 бит, и получить 24 из расширения структурно невозможно.**
`generateRandomMnemonic()` не принимает параметров, `createNewVaultAndKeychain`
передаёт только `{ type: hd }`. Нет ни одной точки, через которую можно
запросить 256 бит.

**[код]** У `randomBytes` **нет запасной ветки**: если Web Crypto недоступен,
она бросает исключение, а не деградирует в `Math.random`. Именно такая
деградация утопила Profanity.

**[код]** CSP расширения — `script-src 'self' 'wasm-unsafe-eval'`: удалённый
скрипт исполниться не может, вся криптография внутри CRX.

**[код] Телеметрия секреты нести не может, и это обеспечено allowlist'ом.**
`maskObject` в `shared/lib/object.utils.ts:50-67` заменяет всё, что не помечено
`true`, на *строку с именем типа*. В маске `keyrings: false` → уедет строка
`"object"`; `vault` в маске отсутствует вовсе → уедет строка `"string"`.
В Sentry не попадёт даже шифротекст.

**[док]** Аудит: Least Authority, «MetaMask Extension: Seed Phrase Implementation
Security Audit Report», 29.07.2022 — выделенный аудит именно этого пути.
Замечания касались операционной безопасности, не ГСЧ.

### 12 слов — это не слабость

Практический уровень стойкости secp256k1 всё равно ~128 бит (метод Полларда-ро).
Перебор 12-словной фразы стоит ~2¹³⁹ операций против ~2¹²⁸ для атаки на
публичный ключ — то есть фразу рациональный атакующий вообще не тронет.
Разница между 12 и 24 словами проявляется только против Гровера по адресу,
который ещё ни разу не тратил. Подробнее: [ENTROPY.md](ENTROPY.md).

## 2. Единственное, что нужно проверить самому

**Если при установке вы входили через Google или Apple — это был путь
`socialCreate`, и зашифрованная копия фразы лежит на серверах MetaMask.**

**[код]** Генерация на этом пути байт-в-байт та же и локальная, но затем
вызывается `createSeedPhraseBackup` → `SeedlessOnboardingController.ts:639`,
где фраза шифруется ключом, выведенным из пароля, и выгружается.

**[не подтверждено]** Путь до самого HTTP-вызова не прослежен, схема TOPRF
не аудирована. Поэтому утверждение «MetaMask не может расшифровать вашу копию»
здесь **не подтверждается** — оно опирается на свойства TOPRF и на стойкость
вашего пароля.

> **Проверка без чтения кода:** если вам показали 12 слов, заставили записать
> и переспросили, и вы **не** использовали вход через соцсеть — это был путь
> `create`, и с машины не ушло ничего.

## 3. Самое слабое место: хранилище держится на одном пароле

**[код]** На диск попадает только шифротекст (`vault: { persist: true }`,
`keyrings: { persist: false }`), но внутри него — сама мнемоника.

| Параметр | Значение | Источник |
|---|---|---|
| KDF | PBKDF2-HMAC-SHA256 через WebCrypto | `browser-passworder/src/index.ts:338-351` |
| Итерации | **600 000** | `metamask-controller.js:1008`, `encryptorFactory(600_000)` |
| Шифр | AES-GCM, ключ 256 бит | `src/index.ts:42`, `:351` |
| Соль | 32 случайных байта, рядом открытым текстом | `src/index.ts:415` |
| IV | 16 свежих случайных байт | `src/index.ts:123` |
| Привязка к устройству | **отсутствует полностью** | `keyFromPassword(password, salt)` |

**Ключ выводится из пароля и соли — и больше ни из чего.** Ни Keychain,
ни Secure Enclave, ни TPM, ни отпечатка машины, ни серверной части.
**Файл переносим и взламываем офлайн:** скопируйте его на любую другую машину,
и он расшифруется точно так же.

Лучшее доказательство принятой модели угроз — собственный
[vault-decryptor](https://metamask.github.io/vault-decryptor) от MetaMask:
статическая страница на GitHub Pages, которой достаточно файла и пароля.
Ни привязки к устройству, ни аттестации, ни ограничения частоты попыток.

**[код]** Тонкость, которую цитируют неверно: дефолт библиотеки — **900 000**,
MetaMask сознательно понижает до 600 000 (цифра OWASP 2023).
В блогах встречается 900k — это не про вас.

**[код] Старые хранилища перешифровываются автоматически** при первом же вводе
пароля, начиная с v11.8.0 (31.01.2024). `submitPassword()` проверяет
`#isNewEncryptionAvailable()`. Кэш-ключ живёт в `chrome.storage.session` и не
переживает перезапуск браузера, поэтому любой, кто с января 2024 хоть раз
перезапускал Chrome, уже обновлён. Проверить: в JSON хранилища есть поле
`keyMetadata` → 600k, нет → 10k.

**[код]** Шифротекст лежит **в двух местах**: `Local Extension Settings`
(LevelDB) и зеркало в IndexedDB (`persistence-manager.ts`, БД
`metamask-storage-service`). Очистка одного каталога не удаляет второй.

**[не подтверждено]** Точный путь `~/Library/Application Support/Google/Chrome/
<Profile>/Local Extension Settings/nkbihfbeogaeaoehlefnkodbefgpgknn/` — это
поведение Chrome, а не то, что читается в исходниках MetaMask.

## 4. Сколько стоит взломать ваш пароль

**[док]** Замеры hashcat на **одной RTX 4090**; два независимых режима сходятся
в пределах 5%, поэтому линейное масштабирование корректно. Таблица для стойки
из восьми карт, время **ожидаемое** (половина пространства перебора):

| Пароль | при 10k итераций | при 600k |
|---|---|---|
| Словарь + правила (33 бита) | 12 минут | 12 часов |
| Большой словарь (40 бит) | 21 час | 51 день |
| 8 случайных `a-z0-9` (41 бит) | 2.4 дня | 145 дней |
| **4 слова Diceware / 10 случайных (52 бита)** | 8.5 лет | **510 лет** |
| 5 слов Diceware (65 бит) | 66 тыс. лет | 4 млн лет |

**600k итераций покупают около 5.9 бита стойкости пароля.** Это не замена
энтропии. Порог реальной безопасности — **5 слов Diceware или 12 случайных
символов**.

**[док]** Стоковый hashcat **не умеет** 600k: в режимах 26600/26610 значение
10 000 зашито, нужна пересборка. Для компетентного атакующего тривиально,
для массового — реальный барьер.

## 5. Что делать за минуту

**[код] Автоблокировка выключена по умолчанию.**
`shared/constants/preferences.ts:13` — `DEFAULT_AUTO_LOCK_TIME_LIMIT = 0`,
а контроллер документирует: при нуле таймер не создаётся. Из коробки кошелёк
остаётся разблокированным до конца сессии браузера.

**Settings → Security & Privacy → Auto-lock timer → 5–15 минут.**
Самое дешёвое действие из всего списка.

**[код]** При блокировке ссылки на ключи сбрасываются (`setLocked()`), но это
**не затирание**: строки JS неизменяемы, байты остаются в куче и могут уйти
в swap.

## 6. Почему стилеры целятся именно сюда

**[док]** Каталог `Local Extension Settings` — явная цель у AMOS/Atomic
([разбор Objective-See](https://objective-see.org/blog/blog_0x88.html) содержит
захардкоженный ID `nkbihfbeogaeaoehlefnkodbefgpgknn` с комментарием `# MetaMask`),
Lumma, RedLine, K1w1.

Механика важна: **расшифровать они не могут.** Они массово собирают шифротекст,
отправляют на C2, а перебор идёт офлайн — со словарём, **персонализированным из
паролей браузера и буфера обмена, собранных на том же хосте в том же проходе**.
Поэтому переиспользование пароля здесь катастрофично.

**Следствие: если машина была скомпрометирована — считайте сид скомпрометированным
и переводите средства, независимо от стойкости пароля.** Смена пароля не поможет:
у атакующего снимок *старого* шифротекста.

## 7. Итог

| | |
|---|---|
| Генерация | В порядке. Локальная, 128 бит из CSPRNG ОС, без деградации ГСЧ |
| 12 слов | Не слабое место — потолок ставит кривая, а не длина фразы |
| Телеметрия | Секреты нести не может, обеспечено allowlist'ом в коде |
| **Хранилище** | **Слабое место. Один пароль, переносимый файл, офлайн-перебор, две копии на диске** |
| Автоблокировка | **Выключена по умолчанию** |
| Соц-вход | Зашифрованная копия на серверах; её криптография нами не проверена |

Это нормальная модель для **горячего** кошелька и неприемлемая для сбережений.
Разделяйте: небольшой расходный остаток в расширении, сбережения — на отдельной
сид-фразе, сгенерированной этим инструментом офлайн или аппаратным кошельком.
