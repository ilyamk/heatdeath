```sh
rm -rf node_modules && npm ci --ignore-scripts
npm run build        # -> dist/
npm run sign         # -> подписи (нужны ключи в keys/)
npm run verify-release
```

## Что делает `build.sh`

Каждый шаг — гейт: сборка падает, а не выпускает сомнительный артефакт.

1. Печатает версии Node и esbuild, предупреждает при расхождении с рецептом.
2. **Self-test из исходника.** Не собирать непротестированное.
3. Бандл через esbuild: из корня, относительный путь входа, формат ESM.
4. **Проверка бандла в изоляции** — копия во временный каталог без
   `node_modules`, там `--self-test`.
5. Single executable через `node --build-sea`, затем ad-hoc `codesign`.
6. **Проверка песочницы бинарника** — требуется ровно `6/6 denied`, иначе FATAL.
7. **Проверка, что `NODE_OPTIONS` не ослабляет песочницу** — попытка записи
   в `/tmp`; если файл появился, сборка падает.
8. Манифест `SHA256SUMS` и `BUILD-RECIPE.txt`.

## Конфигурация SEA

`build/sea.json`:

```json
{
  "main": "../dist/heatdeath.mjs",
  "mainFormat": "module",
  "output": "../dist/heatdeath",
  "execArgv": ["--permission", "--allow-fs-read=/dev/urandom"],
  "execArgvExtension": "none"
}
```

Три ключа, каждый обязателен, и каждый неочевиден:

**`mainFormat: "module"`.** Без него точка входа исполняется как CommonJS и
падает с `SyntaxError: Cannot use import statement outside a module`. Именно
поэтому распространено мнение, что SEA не умеет ESM — умеет, начиная с этого
ключа. Обходной путь через конвертацию в CJS не работает: `esbuild --format=cjs`
отказывается из-за top-level `await`.

**`execArgv`.** Запекает флаги в бинарник навсегда. Проверять результат надо
через `process.permission`, а **не** через `process.execArgv`: флаги
применяются до пользовательского кода и в `execArgv` не отражаются, там пустой
массив. Это распространённый источник неверного вывода.

**`execArgvExtension: "none"` — не опция, а требование.** По умолчанию `"env"`,
и тогда `NODE_OPTIONS` **расширяет** запечённые флаги. Измеренная разница на
двух идентичных бинарниках:

```
"none" + NODE_OPTIONS=--allow-fs-write=/tmp  ->  6/6 denied, файл не записан
"env"  + NODE_OPTIONS=--allow-fs-write=/tmp  ->  5/6, file write ALLOWED
```

То есть с дефолтом любой, кто контролирует окружение, снимает песочницу
переменной среды. Шаг 7 в `build.sh` существует именно поэтому.

Бинарнику нужен доступ **только** к `/dev/urandom`: всё остальное вшито в
бандл, каталог пакета читать не требуется.

## Детерминированность

| Артефакт | Воспроизводим | Условие |
|---|---|---|
| `heatdeath.mjs` | да | та же версия esbuild, запуск из корня с относительным путём |
| `heatdeath` | да | та же сборка Node (v26.5.0, darwin/arm64), то же имя выходного файла |
| Подписи | **нет** | ML-DSA рандомизирована; манифест при этом идентичен |

Абсолютный путь ко входному файлу протекает в бандл комментариями и делает хеш
машинозависимым. Имя выходного файла бинарника участвует в ad-hoc подписи как
идентификатор, поэтому переименование меняет байты.

## Ключи подписи

`npm run sign` при первом запуске генерирует три пары и кладёт приватные в
`keys/` с правами `0600`. Каталог в `.gitignore`.

- **Утечка ключей** = атакующий подписывает бэкдоренную сборку, и она
  проверяется идеально.
- **Потеря ключей** = вы больше не можете подписывать под той же личностью,
  и пользователям придётся заново пинить новые отпечатки.

Держите `keys/` вне машин, не участвующих в релизе.

## Другие рантаймы

Проверялись, оба отклонены:

**Deno** — лучшая песочница из трёх: выйти из неё не удалось ни через
`--allow-all` в рантайме, ни через переменные окружения; флаги не лежат
открытым текстом; 64 МБ и кросс-компиляция на шесть платформ. Инструмент
проходит self-test под Deno, то есть совместимость `node:crypto` покрывает
`pbkdf2Sync`, `createHmac` и `timingSafeEqual`, и обе независимые реализации
переживают порт. **Но `deno compile` не воспроизводима** — два прогона
расходятся. Воспроизводимость важнее качества песочницы, потому что бэкдор в
ГСЧ обходит песочницу целиком: ему не нужны никакие разрешения.

**Bun** — 61 МБ, self-test проходит, но **модели разрешений нет вообще**:
`--prove-sandbox` даёт 2/6, и инструмент отказывается себя сертифицировать.
Дисквалифицирован.

## Кросс-платформенность

Node SEA **не умеет кросс-компиляцию**. Текущий релиз — только darwin/arm64,
собранный и проверенный на целевой платформе. Для остальных платформ нужны
раннеры CI; пользователям на Linux и Windows остаётся бандл `.mjs`, который
работает везде, где есть Node.

Это осознанный выбор: непроверенный бинарник для платформы, на которой его
никто не запускал, хуже, чем его отсутствие.
