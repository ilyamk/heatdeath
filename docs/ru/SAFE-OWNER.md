# Церемония cold/recovery owner для Safe

[← Вся документация](../../README.ru.md#документация) · [🇬🇧 English](../en/SAFE-OWNER.md) · [📖 Глоссарий](GLOSSARY.md)

HEATDEATH создаёт один EOA по пути `m/44'/60'/0'/0/0` для роли холодного или
редко используемого recovery owner в Safe. Инструмент не разворачивает и не
инспектирует Safe, не выбирает threshold и не подписывает транзакции. Импорт
фразы в онлайн-кошелёк прекращает её холодный статус.

## Правила безопасности

- Генерируйте каждого Safe owner из независимого seed, желательно на независимом железе.
- Никогда не выводите несколько owners из этой фразы: несколько видимых подтверждений
  иначе будут зависеть от одного скомпрометированного корневого секрета.
- Для основных signer-ключей с крупными суммами выделенное устройство с собственным
  доверенным экраном остаётся сильнее компьютера общего назначения.
- Поддержка, maintainer и участники design-partner сессий никогда не должны видеть
  реальную фразу, долю, приватный ключ, финансируемый адрес или баланс.

## Сначала репетиция

Репетиция использует официальный публичный 24-словный вектор с нулевой энтропией
и закреплённый публичный owner address. На каждом экране написано
`PUBLIC TEST DATA - NEVER FUND`.

```sh
npm run rehearse:safe-owner
```

В этом режиме нет секретов. Не вводите в него реальный seed или passphrase.

## Проведение церемонии

Используйте чистую физическую машину, отключите сеть и запись сессии, затем выполните:

```sh
npm run doctor
npm run safe-owner
```

Сценарий требует Node Permission Model, выполняет полный self-test, предлагает
физические кубики, независимо перепроверяет деривацию, убирает фразу с экрана перед
обязательным вводом с бумаги и печатает один checksummed owner address и QR только с адресом.

Пустая BIP-39 passphrase — операционно более простой default для командного recovery key.
Если passphrase установлена, храните её отдельно: доли SLIP-39 её не содержат, а потеря
passphrase навсегда уничтожает доступ.

Опциональные доли 2-of-3 несут BIP-39 entropy, а не нативный для Trezor SLIP-39 seed.
Восстанавливайте их командой `combine` из HEATDEATH.

## Независимая проверка перед настройкой Safe

Завершите первую сессию. В новой офлайн-сессии введите фразу с бумаги:

```sh
npm run verify -- --accounts=1 --qr
```

Сверьте фиксированный путь, master fingerprint и полный checksummed address. Второй
участник должен сравнить адрес с owner, добавляемым в Safe. Проверьте процедуру
восстановления организации до появления существенных средств в Safe.

Если ключ пришлось активировать, зафиксируйте когда, зачем и куда импортировали фразу.
После импорта в сетевой кошелёк это больше не cold owner; замените его в Safe по
утверждённой процедуре организации.
